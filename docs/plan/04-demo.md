## 4.4 Rehearsal checklist (before every take)

1. `lq doctor` all green; `lq seed --demo --reset --anchor-date <today>` (fresh ledger, dates correct for the recording day).
2. Docker Desktop running; Console open; server running; Mattermost reachable; project-room `!agents-status` shows its expected members live.
3. Stop prior take sessions and serialize runs; select one active ledger path before starting fresh sessions. Use the four-agent core room; import the core template and verify all four expected agents respond before recording (UNVERIFIED until exercised). If the optional project template is exercised, `project=egcg-take<N>` produces `rao-proj-egcg-take<N>`; verify five project members, three HQ members and three HQ roles. Five identities can mean eight sessions for one project. Measure RAM after three takes and require >=20% headroom.
4. In each new room run and verify `!follow-ups off` and `!unassign-agent` where supported. Use targeted `!reset <agent>` when needed; wait for live. Check actual room membership with `!agents-status`.
5. Two Chrome profiles signed in (`prof-rao`, `maya`), zoom 110-125%, same theme, notifications muted, bookmarks bar hidden, 1920x1080, OBS scene ready.
6. Wispr Flow running with dictionary and snippets loaded; microphone tested; mention-first phrasing on a cue card; Wispr style set so no period lands after a mention.
7. Power plan never sleep; Windows Focus Assist on; Docker and Console minimized.
8. Run the Playwright smoke spec (`pytest -m e2e -k smoke`, about 4 min) and confirm pass.
9. No secrets, tokens or private URLs visible in any window or address bar.

## 4.5 Fallback plan if a live agent misbehaves

| Failure | On camera | Off camera |
| --- | --- | --- |
| Agent silent more than 45 s | Type `!agents-status`; if it shows no session, say only what the status actually reports | Restart the session in Console, retake the segment |
| Agent wanders (wrong slot, chatter) | Do not argue on camera; cut | Tighten the instructions, add a replay scenario test, retake |
| Approval card does not appear | Cut | Separate MCP launch failure from effective settings failure. CLI gate-only profile is eligible only when enforcement passed and MCP launch alone failed; rerun card, bypass and session tests. If enforcement fails, repair it or use the tested steward, never reuse the same ignored settings. |
| Scholarly API outage | Scout reports `UNREACHABLE` honestly (also a feature) | Set `LQ_HTTP_MODE=replay` for the take and show the replay caption |
| Run unrecoverable | - | Use one uninterrupted successful causal run; log room, seed, request revision, dataset hashes and run/draft IDs. A reseeded retake is labeled as a new scenario and never implied to continue the earlier run. |
| Provider down | - | For read/propose agents use an already-tested alternative and disclose it. For `@pi-desk`, use the known-good baseline or rerun S2/S3a-c and affected E2E on the alternative before filming. |

Never draw fake approval buttons, never present a deterministic replay as a live model run, and never present an offline mock as live Switch.
